## 2. Сервер

| Технология   | Версия  | Лицензия     | Роль в проекте                               |
| ------------ | ------- | ------------ | -------------------------------------------- |
| Node.js      | 22.18.0 | MIT          | Среда исполнения                             |
| Express      | 5.2.1   | MIT          | HTTP-фреймворк, раздача статики клиента      |
| Zod          | 3.25.76 | MIT          | Валидация тел запросов                       |
| jsonwebtoken | 9.0.3   | MIT          | Выдача и проверка JWT (срок 12 ч)            |
| bcryptjs     | 3.0.3   | BSD-3-Clause | Хеширование паролей                          |
| tsx          | 4.23.15 | MIT          | Запуск TypeScript в dev-режиме (`tsx watch`) |

Хранилище — локальный JSON-файл через `server/src/shared/db.ts`, без внешней СУБД. Запись
выполняется через временный файл и атомарное переименование. В Electron путь задаётся через
`RLS_DATA_DIR` в каталоге `userData`; сервер без этой переменной использует `~/.rls-simulator`.
Секрет JWT хранится в том же файле; переменная `JWT_SECRET` позволяет задать постоянный секрет
вручную (минимум 32 байта UTF-8). API работает на loopback и не использует CORS: dev-клиент
обращается к нему через Vite proxy, Electron — через handler `app://rls.local`.

## 3. Десктопная оболочка

| Технология | Версия | Лицензия | Роль в проекте                                  |
| ---------- | ------ | -------- | ----------------------------------------------- |
| Electron   | 44.5.1 | MIT      | Окно десктопного приложения 1440×900 (п.2.1 ТЗ) |

`desktop/main.cjs` запускает собранный сервер как дочерний процесс через IPC, получает его
динамический loopback-порт и обслуживает renderer по постоянному адресу `app://rls.local`.
Обработчик протокола раздаёт файлы клиента и проксирует API-запросы; отдельный HTTP-сервер
для renderer не нужен.
